Core Concept Adversarial Debate Architecture

Single-prompt LLMs fail in capital markets due to confirmation bias, hallucinations, and unverified data. ThesisForge AI decomposes equity research into a specialized adversarial committee:

  • Research Agent: Unbiased factual extraction via hybrid BM25 document RAG.
  • Bull & Bear Agents: Specialized advocates bound strictly to cited evidence IDs.
  • 1-Turn Rebuttal: Bounded dialectic round targeting the opponent's strongest argument.
  • Risk Agent: Empirical quantitative safety gate with autonomous veto authority.
  • Judge Agent: Impartial synthesis constrained solely to validated evidence ledger facts.

Problem Formulation: Why Adversarial Debate & Bounded Rebuttal?

Overcoming Single-Prompt LLM Pathologies in Financial Decision Making

Critical Failure Modes Single-Prompt LLMs in Capital Markets
  • Confirmation Bias: Single prompts parrot the tone of the user's question, ignoring downside insolvency risks.
  • Financial Hallucination: Inventing PE multiples, forward guidance, and margins with ungrounded confidence.
  • Infinite Dialectic Drift: Unstructured multi-agent chats spiral into circular arguments without convergence.
  • Neglect of Asymmetric Downside: In equity research, losing $100\%$ on bankruptcy is far worse than missing a $15\%$ upside.
The ThesisForge Solution Dialectic Decomposition & Safety Gates
  • Role Specialization: Bull Agent maximizes upside catalysts; Bear Agent relentlessly probes vulnerabilities.
  • Strict Evidence Grounding: Un-cited assertions are programmatically stripped before reaching the Judge.
  • Deterministic 1-Turn Rebuttal: Attacks only the highest-ranked opposing claim; terminates in guaranteed $O(1)$ time.
  • Autonomous Risk Veto: Empirical quantitative threshold ($\ge 0.65$) halts speculative BUY calls on debt distress.
The Four Non-Negotiable Laws of the Investment Committee
1. Neutral Discovery: Research Agent never issues stances; only extracts verified facts into EV-xxx.
2. Evidence Citation: Every factual claim in Bull/Bear briefs must carry a valid citation.
3. Bounded Debate: Exactly 1 rebuttal response per side to avoid circular reasoning.
4. Safety Superiority: The Risk Agent veto is absolute and overrides the Judge to HOLD.

The 9 Deterministic Workflow Stages
1. INITIALIZED ──► Asset validation & document pack loading
2. FACT_RETRIEVAL ──► Research Agent BM25 search ──► Evidence Ledger
3. BULL_ARGUMENTATION ──► Positive thesis creation with [EV-xxx] citations
4. BEAR_ARGUMENTATION ──► Negative thesis creation with [EV-xxx] citations
5. REBUTTAL_ROUND ──► Argument ranking & 1-turn targeted rebuttal
6. RISK_EVALUATION ──► Quantitative risk composite & covenant audit
7. JUDGE_DELIBERATION ──► Evidence-bounded synthesis (BUY / HOLD / AVOID)
8. VALIDATION_AND_VETO ──► Citation verification & Risk Veto enforcement
9. REPORT_FINALIZATION ──► Actionable Signal Card & SHA-256 event append
State Machine Resilience & Error Handling

Unlike fragile chaining systems, every state transition is wrapped in deterministic guards. If an asset has 0 documents (e.g. HDFCBANK), the state machine halts at Stage 2, records an honest INSUFFICIENT_EVIDENCE event, sets recommendation to HOLD, and bypasses speculative trade cards.

Slide 06 • RAG & Grounding Engine 06 / 10

Document-Based RAG, Evidence Ledger & Citation Validation

Eliminating Hallucinations through Cryptographic Chunking and Citation Auditing

1. Ingestion & Retrieval Pipeline

Text Extraction: Parses official PDF/TXT filings, preserving statutory sections and page numbers.

Deterministic Chunking: 500-character window with 100-character sliding overlap.

Hybrid Retrieval: Tokenized BM25 ranking filtered strictly by asset_id to prevent cross-company data leakage.

Stable Registry: Chunks assigned immutable IDs (EV-001, EV-002...) linked to file source and page.

SELECT chunk_id, content, page_no 
FROM document_chunks 
WHERE asset_id = :target_asset 
  AND bm25_match(content, :query)
2. Strict Citation Validation Engine

Regex Pattern Match: Scans all agent claims for citations matching \[(EV-\d{3})\].

Existence Audit: Every cited ID must exist in the active run's evidence ledger.

Claim Stripping: If an agent states a financial fact without an evidence ID or uses an invalid ID, the validator rejects the claim.

Judge Evidence Constraint: The Judge prompt and validation layer forbid introducing facts outside the Bull/Bear evidence packs.

# validation_tools.py
valid_ids = {e.evidence_id for e in evidence_pack}
for claim in argument.claims:
    if not all(cid in valid_ids for cid in claim.evidence_ids):
        reject_claim(claim, reason="Ungrounded citation")

Bulletproof Viva Q&A Strategy

Q1: Why separate agent modules instead of one prompt with tools?
Answer: A single prompt cannot enforce true adversarial independence. Attention bleed causes the model to compromise prematurely. Separate modules enforce independent system prompts, distinct tool permissions, and isolated validation.

Q2: How do you guarantee the Judge doesn't hallucinate facts?
Answer: The Judge prompt and validation layer (validate_all_citations) constrain deliberation strictly to evidence IDs established in the active run's ledger. Any ungrounded claim is rejected.

Q3: What makes the rebuttal round bounded?
Answer: In unconstrained chat, agents loop indefinitely. We implemented a 1-turn rebuttal algorithm: rank_arguments identifies the opponent's strongest point, and each debater executes exactly one response targeting that specific claim. Time complexity is O(1).

Q4: How does the Risk Agent veto operate?
Answer: risk_agent.py evaluates leverage and covenant compliance. If the empirical risk score crosses 0.65, enforce_risk_veto forces the final recommendation to HOLD, overriding the Judge.

Q5: What frameworks and technologies did you use?
Answer: Python 3.13, Microsoft Semantic Kernel adapter, FastAPI backend, SQLite database, Pydantic v2 data models, and an HTML5/CSS3/JavaScript responsive web interface.
